## 1. 产品定位与范围

### 1.1 一句话定义

面向 Windows 的**开放式语音唤醒对话平台**:免手动、免热键,说一句唤醒词 —— 确认是本人的声音 —— 唤醒球弹出,简单的事平台自己做,复杂的事派发给外部 agent 并汇总结果,全过程本地优先、有记忆、可打断。

原型阶段(Phase 3)的定位是「EvoX 本地语音唤醒对话客户端」;Phase 4 起 EvoX 降级为**众多 agent 后端之一**,平台不再绑定单一后端。

### 1.2 目标用户与场景

| 场景 | 描述 |
|---|---|
| 双手占用 | 用户在写代码/看文档时不切窗口,直接语音提问 |
| 常驻待命 | 唤醒球悬浮桌面底部,不占任务栏、不抢焦点 |
| 连续追问 | 一次唤醒后可多轮对话,无需重复唤醒词 |
| 随时打断 | 回复过程中说话或点击即可中断,立即进入下一轮 |
| 只认本人 | 电视里、同事嘴里、隔壁房间的同一句唤醒词**不得**驱动系统 |
| 平台自办 | 「读一下 X 文件」「搜一下 Y」这类请求本地直执行,毫秒级,不派发 |
| 派发外包 | 需要推理的请求交给 claude / codex / opencode / hermes,流式出字 |

### 1.3 明确不做(out of scope,范围外)

- 不做云端语音识别/合成(违反本地优先红线)
- 不做多语言唤醒(v1 仅中文 `你好问问`)
- 不做移动端与 macOS/Linux(v1 仅 Windows x64)
- 不做会话历史管理界面(由各 agent 后端负责)
- 不保存任何音频文件
- 不做声纹反欺骗(anti-spoofing)模型 —— 录音回放本轮只验证与记录,不检测(ADR 002 局限)
- 不做向量检索与知识图谱记忆 —— SQLite + FTS5 够用(ADR 004)
- 不做学习式路由 —— 规则加统计打分够用(ADR 005)
- 不以 OpenClaw 为底座,不引入长驻 Node.js 进程作为必需依赖(ADR 003)
- 不把本平台暴露为 MCP server(反方向需求,等平台自身跑通再说)

> **2026-08-02 变更**:原「不做语音账号识别/声纹」一条**已删除并反转** —— 声纹准入现在是 P0 需求(FR-8)。理由:KWS 只判「有没有说这个词」,不判「是谁说的」;一旦平台获得读文件与跑终端命令的能力,这就从体验问题变成安全问题。

> **FR-1.8 的原始表述无法满足,已按实测改写(2026-08-02)。** sherpa-onnx 1.13.4 的 `KeywordResult` 只有 `keyword` / `timestamps` / `tokens`,`KeywordSpotter.get_result()` 返回裸 `str` —— **这个绑定根本不暴露单次命中的置信度**。原代码写 `1.0`,看起来像测量值而不是测量值。现在 `feed()` 返回 `(keyword, None)`,`None` 是一个经核实的陈述而非遗漏;进入 `wake.detected` 的分数改为声纹余弦相似度,那个数字**是**测量出来的。详见 ADR 002 与 `docs/research/prototype-results.md`。

### 4.2 发布必过清单(Definition of Done)

一个需求只有满足以下全部条件才算完成:

1. 功能在**真实 Windows 主机**上可用(不是 mock、不是 headless)
2. 有自动化测试覆盖核心路径
3. 失败路径有明确诊断输出,不静默失败
4. 资源(设备、原生句柄)确认释放
5. 验证等级与实测数据记入 `prototype-results.md`
6. 相关例程写入 `routines.md`

## 5. 需求统计

| 优先级 | 总数 | 已完成 | 部分完成 | 未实现 |
|---|---:|---:|---:|---:|
| P0 | 77 | 30 | 10 | 37 |
| P1 | 20 | 6 | 3 | 11 |

| **合计** | **99** | **38** | **13** | **48** |

需求总数从 40 涨到 99,是 Phase 4 平台化的直接结果:声纹准入 14 条、平台工具 9 条、agent 接入 10 条、派发汇总 9 条、记忆 9 条,唤醒球与诊断各补 4 条、3 条。

P0 完成率从原来的 61% 降到约 39% —— **这不是退步,是分母变大**:同一批原型能力现在要服务一个平台而不是一个客户端。缺口集中在五处:平台层五个包的实现(P3–P7)、声纹门接线(P1)、流式 ASR 与 TTS 播放、真实后端联调(REAL-EVOX / REAL-AGENT)、真机窗口验收(REAL-WIN)。

**「部分完成」的 13 条一律不得当已完成用**:其中 10 条是 P0,多数是「契约就绪、实现未接」或「SIM 已过、真机未验」。
