# ADR 009：识别上云（`qwen-audio-3.0-asr-flash`）

- 状态：已接受
- 日期：2026-09-03
- 决策者：使用者（原话：「不要再考虑本地模型了，现在全云端模型，优化现在的云端模型调用和切换」）
- 影响：红线 1 的措辞、`core/audio/asr_cloud.py`（新）、`config/voice.toml` 的 `[asr]`、
  `config/models.toml` 的 `[profiles.local.asr]`、`core/models_config.py` 的 `PROTOS`
- 取代：ADR 001 里「ASR 走本机流式 zipformer」那一条（本机那条路仍然在，见「怎么换回去」）

## 背景

使用者在四轮对话里三次报同一件事：**「语音转文字还是不够精准」**。前两轮的处理都落在
参数上（束宽 4 → 16、热词表、自适应增益），第三轮他说「我已经按照你给的指令构建并重启了」
而症状没变 —— 那时才值得怀疑参数不是原因。

## 证据

**E1 —— 同一条真录音，两条路各跑一次**（`.vox-ref/rec/你好小沃 检查目前运行状态是否正常.wav`，
16 kHz 单声道 7.15 s，本人真录）：

| 路 | 转写 |
|---|---|
| 本机 `sherpa-onnx-streaming-zipformer-zh-14M` | 你好小**吴**检查目前运行状态是否正常 |
| 云端 `qwen-audio-3.0-asr-flash` | **你好，小沃，检查目前运行状态是否正常。** |

**E2 —— 为什么参数救不回来**：本机那个模型的 `tokens.txt` 里只有 **1426 个汉字**，
「沃」不在里面。它**写不出**这个字。热词表（上下文偏置）在解码时给候选路径加分，而一个
不在字表里的字根本没有候选路径可加 —— 实测把 21 行热词喂进去，其中 8 行含它写不出的字
（沃 / 酷 / 哔 / 哩 / 抖 / 浏 / 览 / 唤 / 纹），sherpa-onnx 只在 C++ 层打
`Cannot find ID for token`，Python 侧一个字都看不见。

**E3 —— 使用者报的 400 的真正原因**。他配的端点是 `compatible-mode/v1`（OpenAI 协议）。
四种形状各发一次：

| 请求 | 结果 |
|---|---|
| 原生端点 + `data:audio/wav;base64,…` + `parameters.format` | **200，转写正确，7.8 s** |
| 原生端点 + 旧式 `{"audio": "data:…"}` 键 | 200，转写正确，4.3 s |
| 原生端点 + **裸 base64**（不带 `data:` 前缀） | 500 `Cannot run program "/usr/bin/wget": Argument list too long` |
| 原生端点 + **缺 `parameters`** | 400 `UNSUPPORTED_FORMAT: format is empty` |
| **`compatible-mode/v1`**（他配的那条） | 400 `UNSUPPORTED_FORMAT: format is empty`，25.4 s |

第三行说明服务端把不带前缀的字符串**当 URL 拿 wget 去下载**。第五行是那个 400 的全部
内容：这个模型要 `parameters.format`，而 OpenAI 协议里**没有地方放它**。

**E4 —— 端到端跑一遍（走 provider 契约，按 100 ms 真实节奏喂）**：

| 样本 | 转写 | 端点判出 | 文本到手 | 段长 | 往返 |
|---|---|---|---|---|---|
| 7.15 s（中途 1.9 s 停顿） | 你好，小沃检查目前运行状态是否正常。 | 3.2 s | 11.3 s | 两段共 4.9 s | 3.1 s |
| 2.64 s | 你好，小沃。 | 3.1 s | 7.0 s | 3.1 s | 3.8 s |

第一行是**续说拼接**的读数：1.9 s 的停顿被当成句末发了第一段，而第一段的文本回来时人
已经在说后半句，于是它被认成句中、攒起来等第二段（`continuations = 1`）。

生产上唤醒词由 KWS 吃掉、不进识别流，所以典型一轮是**一段**：说完 → 0.8 s 端点 →
3–4 s 往返 ≈ **说完之后 4–5 秒拿到文本**。这是端点的属性，不是可调项。

## 决策

`[asr].provider` 默认 `"dashscope"`，走**原生多模态端点**
`api/v1/services/aigc/multimodal-generation/generation`，音频以 `data:audio/wav;base64,…`
内联，`parameters.format = "wav"` + `sample_rate = "16000"`。

四条实现约束，每一条都对应上面一个证据：

1. **必须内联，不能给 URL**（E3 第三行）。给 URL 要求先把使用者的录音传到一个公网可取的
   地方 —— 那条路不做。
2. **端点检测本机做**。这个接口不流式（一次 POST 整段），所以「人说完了没有」由已经在盘上
   的 Silero VAD 判（零新依赖）。
3. **HTTP 不在音频回调里发**。`capture._recognize()` 跑在 sounddevice 的回调线程上，在那里
   阻塞 3–8 秒会丢帧，而丢帧的表现是**「识别器听错」而不是「卡住」**。所以 `feed()` 只攒
   样本 + 跑 VAD，判到句末就交给工作线程，之后每一块顺手看一眼好了没。
4. **等云端的那几秒里照常收音频**。使用者不知道自己被切断了，那 3–5 秒里说的话必须还在
   缓冲里 —— 丢掉它的表现是「它总听半句」。

## 隐私姿态：红线 1 改口

**「音频永不出这台机器」这句话不再成立。** 不含糊地写下现在的三条：

- **唤醒词的音频永不出网** —— KWS 在本机，待机时的环形缓冲只在内存里；
- **声纹永不出网** —— 校验、注册、向量全部本机；
- **只有「被接受的唤醒之后说的那一句」会出网**，内联进一次 HTTPS POST，不写盘、不留缓存。

「不写盘」有测试钉死（`test_wav_is_never_written_to_disk`）：整条路上一次 `open(..., "wb")`
都没有，wav 在 `io.BytesIO` 里编完就进请求体。

## 怎么换回去

`config/voice.toml`：

```toml
[asr]
provider = "sherpa"
```

本机那条路（`core/audio/asr.py`）一个字节都没删，测试也都还在。代价是「小沃」会被听成
「小吴」，以及任何不在那 1426 个字里的专名。

## 被否掉的方案

- **继续调本机参数**（热词 / 束宽 / 增益）：E2 说明字表缺字这件事在参数层面无解。热词表
  `config/hotwords.txt` 与 `SherpaStreamingAsrProvider(hotwords_file=…)` 留着 —— 它对
  **在字表里**的专名（网易云、哔哩哔哩里的「网」「易」「云」）确实有用，只是救不了「沃」。
  注意那个文件**不能带 `#` 注释**：带注释的文件会让 sherpa-onnx 在加载时报
  `invalid stof argument`，而那个失败让**整个 ASR 不可用**，不是「热词被忽略」。
- **换一个更大的本机模型**：`multi-zh-hans` 系列里更大的那些字表也有限，而下载 + 常驻内存
  的代价换来的仍然是一个比云端差的结果。使用者已经排除了这条路。
- **走 `compatible-mode/v1` 让三个角色共用一套 OpenAI 客户端**：E3 第五行。这个模型在那条
  协议上**不可能**工作，因为 `format` 无处安放。为此在 `PROTOS` 里加了 `"dashscope"` ——
  一个说不出「这是另一种协议」的配置面会逼人把它写成一个谎。
- **给 provider 装一个 `FallbackAsr`（照 TTS 那样在失败时切本机）**：识别的降级只能发生在
  启动时。一句话说到一半切引擎会让前半段丢在云端、后半段丢在本机，两边都不完整。所以
  选择在开麦之前定下来，缺 key 时**退回本机并在就绪清单上大声说**。

## 未验证

- **REAL-MIC**：以上全部走的是已录好的 wav。真机麦克风 → 唤醒 → 云端转写 → 派发这条完整
  链路需要使用者在场（P10）。
- **费用与限流**：免费额度下的并发限制没有实测。这一层在途请求最多一个（和 TTS 同一个
  立场），但连续对话模式下一轮可能发两三次请求。
- **长句**：最长实测 7.15 s。`max_utterance_s = 30` 那一端（约 1.3 MB 请求体）没打过。
