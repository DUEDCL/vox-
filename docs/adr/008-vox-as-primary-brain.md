# ADR 008：Vox 是主脑，agent 是子代理

> 状态：已采纳（2026-08-29，由使用者直接决定）
> 相关：[ADR 003 agent 接入协议](003-agent-integration-protocol.md) · [ADR 005 派发与工具门](005-task-dispatch-model.md) · [ADR 007 MCP 工具](007-mcp-tools.md)

## 背景：现在 agent 不是子代理，是替身

一句话落到 agent 路由，Vox 就把整轮交出去，自己不再参与 —— 拿到什么就念什么。三条实测
后果：

1. **路由器永远选 relay。** `cost` 与 `latency` 占权重 70%，relay 自报 `cost=2/1500ms`，
   claude 自报 `cost=4/2500ms`。连点名 `code` 能力的任务也给 relay（实测
   `relay scored 0.793`）。而 relay 是唯一**不会做事**的后端。
2. **能力声明与事实不符。** relay 的 `capabilities` 写了 `["code","reason","chat"]`，
   而它连文件都读不了。能力在评分里是闸门，所以这个假声明让它过了闸。
3. **没有 system prompt。** `core/agents/http.py` 只发一条 user message，于是模型看到的
   唯一 system prompt 是中转站注入的那份 —— 实测它说「操作系统是 linux，工作目录是 `/`」，
   于是给 Windows 用户建议 `netease-cloud-music &` 和 PulseAudio。

## 决策

### 1. Vox 主脑，agent 降格成工具

主脑是一个 LLM 规划器，拿到工具表做决策。**子代理是工具表里的一项**，和 `app.open` 平级：

```text
唤醒 → 声纹 → ASR
  ├─ 规则命中（快路径，6 个工具）─────→ 执行，0–16 ms      ← 不变
  └─ 规则未命中 ─→ 主脑（云端 LLM + tools）
                    ├─ 调本地工具 → 答
                    ├─ 自己聊 ────→ 答
                    └─ 派子代理 ──→ 立刻答「我让 X 去做了」
                                      ↓ 后台异步
                                   关键节点播报
                                      ↓
                                   主脑汇总 → 答
```

**规则层保留，不被替换。** 三个理由：语音里 0 ms 与 800 ms 是「即时」与「迟钝」的差别；
规则层全 AUTO 可测，模型层只能测调用形状；模型不可达时规则层仍能开应用、报时间。

### 2. 原生 function calling，不解析文本里的 JSON

**已实测**（2026-08-29，`.vox-ref/probe_tool_calling.py`，HTTP 200）：中转站
`api.justwoker.icu/v1` 的 `claude-opus-5` 支持 `tools` / `tool_calls`。对
「帮我用网易云放首歌」——**正是规则层漏掉的那句**——返回：

```json
{"function": {"name": "app_open", "arguments": "{\"name\":\"网易云音乐\"}"},
 "finish_reason": "tool_calls"}
```

所以主脑用结构化 tool_calls，不用「让模型在文本里吐 JSON 再容错解析」那条脆路。
同一次请求还证明**客户端发的 system message 是被遵守的**（它按「Windows 上的语音助手」
选了 `app_open`，没有再讲 X11）。

### 3. 模型提案，`ToolPolicy` 仍是唯一的门

和 MCP 那一层同一个姿态（ADR 007 第 1 节）：主脑能提案 `shell.run`，提案照样撞在
13 条危险模式和白名单上。**危险模式在代码里、不在配置里**这条不动。

### 4. 回合变异步；打断说话，但不杀任务

现在 `runtime.pump()` 在调用方线程里跑完整轮才返回 —— 一个 5 分钟的子代理任务等于
5 分钟静默。派发后必须立刻返回一句「我让 X 去做了」，任务在后台跑。

**唤醒词的语义因此分裂成两半**：`cancel()` 现在同时停 TTS、停 transport、发
`turn.cancelled`。改成 **打断只停「正在说的话」，后台任务继续跑**。理由是使用者点名的：
一个跑了三分钟的任务不该因为用户插了一句「现在几点」就白跑。

### 5. 只在关键节点播报：开始、卡住、完成

不是每有新增量就说。语音里说太密比不说更烦。三个节点：

| 节点 | 说什么 |
|---|---|
| 开始 | 「我让 claude 去做了，大概要几分钟」 |
| 卡住 | 一段时间没有新 chunk 时说一次（阈值待实测定） |
| 完成 | 主脑汇总后的口语版结果 |

原料来自 `output = "jsonl"`：`claude` 改配 `["-p", "--output-format", "stream-json"]`，
适配器**已经支持** jsonl，于是 Vox 能拿到结构化的工具调用事件（「正在读 foo.py」）
而不是从一坨文本里猜进度。

### 6. 督促用「旁听 + 重发」，不用「追问」

`cli.py` 是一次性的（一个 `Popen` + `wait()`，跑完就退）；`acp.py` 建了 session 但只往里
发一个 prompt。所以「对正在干活的子代理追问」在现有两个适配器上**做不到**。

采纳的是：**只旁听输出流当进度，卡住就杀掉、换一个修正过的 prompt 重发**。不改适配器，
拿到大部分价值。`claude --resume` 与「ACP 持久会话」都记在此处作为将来的路，不在本轮。

### 7. 云端算力为主（隐私边界已由 ADR 009 更新）

> **已被 ADR 009 取代（2026-09-03）**：本节早期把 ASR/TTS 也描述为完全本机，现已不再是当前运行规则。保留本节是为了记录当时的架构决策，不应作为当前部署说明。

当前不变式是：

- **唤醒词音频不出网** —— KWS 在本机，待机环形缓冲只在内存里；
- **声纹不出网** —— 注册、校验和向量处理全部在本机；
- **被接受唤醒后的那一句语音**是否出网，由 `config/voice.toml` 的 ASR provider 决定；
- **决策与推理可使用云端算力**，但未经用户主动配置的 telemetry（遥测）仍然不启用。

完整的当前隐私边界、请求形状和切回本机 ASR 的方法见 [ADR 009](009-cloud-asr.md)。
## 后果

**收窄 relay 的能力声明。** `capabilities` 从 `["code","reason","chat"]` 改为
`["chat","reason"]`。更根本的做法是引入一个表达「能不能动这台机器」的能力词
（claude/codex/opencode 有，relay 没有），让「写代码/开项目」这类意图要求它 —— 只改前者
只挡住 `code` 一个词，改后者挡住整类。

**5 维路由 / race-fanout 汇总 / 熔断冻结但不删。** 一台桌面机上 1–3 个子代理，
「优先 claude，不行退 relay」十行就够；那 159 个测试继续跑（保住基线），但不再往里加功能。
自研记忆层同样冻结。这是使用者的选择，理由是重写代价大于留着不长的代价。

**新增的出网面必须说出来。** 规则未命中的每一句转写文本都会发到云端主脑。现在只有落到
agent 的句子出网。控制台要如实显示当前主脑在哪，并且可关 —— 关掉之后退回纯规则层，
能力变少但不失效。
